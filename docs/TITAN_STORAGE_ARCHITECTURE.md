# TITAN storage architecture — experimental rehearsal

## Existing point/observation store
Keep the current production DB, history, pinned backups, three managed verified checkpoints and six-generation backpressure. The 25 Nov production run 45708761078 failed due to checkpoint backlog, not the Drive free-space preflight. Run 45640582238 did not establish redundancy due to a readback failure. Read-only rerun uses rclone cat to local files and validates exact release registration hashes, compressed and restored DB integrity, old-row preservation, and stable inventories. No uploads or retirement to production. If proof fails, keep all checkpoints. Future targeted retirement requires separate review and authorization.

## Spatial storage candidate
Keep regional numerical arrays and original per-model manifests immutable and content-addressed by SHA-256, along with source cycles and acquisition code revision. All 81 lead entries are restored byte-for-byte. Preserve catalog and renderer revisions, data definitions, valid times, native resolutions, windows, model panel references and source manifests. Chart objects are replaceable and independently hashed. Stage and validate everything before a single atomic local pointer update. Keep current and previous complete chart generations; old chart pixels need not be retained unless pinned for a case/report. Numeric objects are never retired in this rehearsal. Same bytes reused without duplication; identical model cycle/lead identity can later be indexed separately, but no deduplication rate across changing real model cycles has been established.

The local rehearsal uses the original and refined full site artifacts, plus a simulated repeat publication of the same frozen numerical fields; it tests interrupted staging, invalid candidates, rollback availability and local fixture-only chart garbage collection. No real forecast acquisition or network storage write. No current live use: stale/expiry policy and multi-writer concurrency are not yet implemented. The metadata-only reports expire in seven days.

## Proposed deployment (not implemented)
Use the existing approved private Drive archive with an isolated spatial prefix for numerical manifests and immutable objects; verify remote quota and readback before any operational publication. Keep a separately approved serving backend for the current and previous chart collections; public GitHub Pages cannot directly serve private Drive files without an authorized delivery mechanism. Do not assume remote atomic rename or local filesystem semantics on Drive. Design a verified manifest-last protocol with a single writer, rollback, expiry gate, and reader consistency; retain orphan/unregistered objects pending reconciliation. No permanent numerical deletion without a reviewed scientific archive policy. Initial 69 MB per collection implies around 101 GB/year at four independent collections/day before deduplication, so measure native cycle reuse and compression over multiple real cycles before choosing long-term retention. This is distinct from the production point-model DB retention problem. Production main untouched.
